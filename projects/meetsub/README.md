## 어떤 문제였나

다국어로 진행되는 회의에서 참여자가 겪는 문제는 두 단계입니다.

**회의 중** — 말을 실시간으로 알아들어야 합니다. 자막이 3초 늦게 나오면 이미 다음 이야기로 넘어가 있습니다. **지연이 곧 쓸모**입니다.

**회의 후** — 무슨 이야기가 오갔는지 정리된 기록이 필요합니다. 여기서는 지연보다 **정확성과 완결성**이 중요합니다. 30초 늦게 나와도 상관없지만 내용이 빠지면 안 됩니다.

이 두 요구는 서로 충돌합니다. 실시간 자막을 정확하게 만들려고 후처리를 붙이면 느려지고, 빠르게 만들면 거칠어집니다.

## 어떻게 풀었나

### 실시간과 후처리를 분리

**같은 세션에서 두 경로를 따로 돌립니다.**

```
음성 ─┬─→ [실시간 경로] STT → 번역 → 자막        지연 최소화
      └─→ [기록 경로]   저장 → 회의 종료 후 처리   정확성 우선
```

자막 경로는 최대한 짧게 가져가고, 요약·리포트·PDF처럼 무거운 작업은 회의가 끝난 뒤에 별도 흐름으로 처리합니다.

이렇게 나누니 각 경로가 자기 목표에만 최적화됩니다. 자막이 조금 거칠어도 실시간성을 지키고, 최종 기록은 시간을 들여 정확하게 만듭니다.

### 세션 단위로 추적

브라우저 연결, 자막 조각, 녹음 파일, 최종 리포트가 **모두 같은 회의 ID로 연결**됩니다.

실시간 스트리밍에서는 연결이 끊깁니다. 네트워크가 불안정하거나, 사용자가 탭을 잠시 닫거나, 서버가 재시작될 수 있습니다. 세션 ID를 축으로 잡으면 **재연결했을 때 이어붙일 수 있습니다.**

## 이 프로젝트에서 배운 것

**같은 데이터라도 용도가 다르면 경로를 나눠야 합니다.** 실시간 자막과 회의 기록은 같은 음성에서 나오지만 요구가 정반대입니다. 하나의 파이프라인으로 둘 다 만족시키려 하면 양쪽 다 어중간해집니다.

**실시간 시스템에서 연결 단절은 예외가 아니라 기본 조건입니다.** 끊기지 않게 만들 수는 없고, 끊겼을 때 이어붙일 수 있게 만들어야 합니다. 세션 ID를 축으로 잡은 것이 그 전제였습니다.
