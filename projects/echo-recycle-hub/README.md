## 어떤 문제였나

분리배출은 규칙이 복잡하고 지역마다 다릅니다. 문제는 **버리려는 물건의 이름을 모를 때** 시작합니다. 이름을 모르면 검색도 할 수 없습니다.

이미지 분류로 종류를 알려주는 서비스는 있지만, 대부분 거기서 끝납니다. **"플라스틱류"라고 알려주는 것만으로는 사용자의 문제가 해결되지 않습니다.** 어떻게 씻어서, 무엇을 떼고, 어디에 버려야 하는지가 실제로 필요한 정보입니다.

## 어떻게 만들었나

### 분류를 행동 안내로 연결

모델의 클래스 이름만 보여주지 않았습니다.

```
사진 촬영 → 분류 → [폐기물 종류]
                    ├── 배출 방법 안내
                    ├── 재활용 추천
                    └── 챗봇으로 추가 질문
```

분류는 시작이지 결과가 아니라고 봤습니다. 사용자가 알고 싶은 것은 "이게 무엇인가"가 아니라 **"이걸 어떻게 해야 하는가"** 입니다.

### 접근 경로 확장

키보드 입력 외에 **STT와 TTS**를 연결했습니다. 손이 젖어 있거나, 화면을 보기 어렵거나, 타이핑이 불편한 상황에서도 쓸 수 있게 하는 것이 목적이었습니다.

AICC 과정에서 배운 음성 인터페이스를 실제 사용 맥락에 붙여 본 시도였습니다.

## 내가 한 일

**기여도 50%** — 팀 프로젝트입니다.

| 영역 | 담당 |
|---|---|
| Architecture | 서비스 구성 설계 |
| Backend | API 및 데이터 흐름 |
| ML | 이미지 분류 모델 적용 |

프론트엔드와 일부 콘텐츠 구성은 팀원이 담당했습니다. **제가 하지 않은 부분을 제 것으로 적지 않았습니다.**

## 결과

교육 과정에서 **최우수 프로젝트**로 선정됐습니다.

| 구성 | 내용 |
|---|---|
| 입력 | 카메라 촬영 · 이미지 업로드 |
| 분류 | 폐기물 이미지 분류 |
| 안내 | 배출 방법 카탈로그 |
| 추천 | 재활용 방안 |
| 대화 | 챗봇 + STT/TTS |
| 인프라 | AWS |

---

## 이 프로젝트에서 배운 것

**모델의 출력이 사용자의 답은 아닙니다.** 분류 정확도를 올리는 데 집중하다 보면, 정작 그 결과로 사용자가 무엇을 할 수 있는지를 놓칩니다. 분류 다음에 무엇이 와야 하는지를 먼저 정한 것이 이 프로젝트의 방향을 정했습니다.

지금 하는 일에서도 같은 판단을 반복하고 있습니다. [Amazon Ads Agent에서 AI의 역할을 '현상 정리'로 한정하고 판단은 사람에게 남긴 것](../amazon-ads-agent/decisions.md#03-ai의-역할을-현상-정리로-한정했습니다)도, 모델 출력과 사용자의 실제 필요 사이의 거리를 다루는 문제였습니다.
