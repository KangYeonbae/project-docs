## 어떤 문제였나

이커머스 광고를 대행하는 조직에서는 매주, 매달 클라이언트에게 광고 성과 리포트를 보냅니다. 그 과정이 이렇게 나뉘어 있었습니다.

1. 담당자가 Amazon 콘솔과 API에서 데이터를 내려받고
2. 엑셀에서 지표를 계산하고
3. 차트를 만들고
4. 문장으로 해석을 쓴다

문제는 속도만이 아니었습니다. **업체마다 리포트 형식과 판단 기준이 달라 비교가 되지 않았고**, 사람이 매번 새로 쓰다 보니 같은 지표를 다르게 해석하는 일이 생겼습니다. 자동화하려고 보니 자동화할 대상 자체가 정의돼 있지 않았습니다.

## 어떻게 풀었나

먼저 자동화가 아니라 **문서 규격 합의**부터 했습니다. 기존 리포트를 직접 수집·분석해 공통 항목을 추리고, 표준 리포트 생성 기준을 정립했습니다.

그다음 시스템을 세 층으로 나눴습니다.

- **수집** — Amazon SP-API와 Ads API에서 21종 리포트를 매일 비동기로 요청·폴링해 BigQuery에 적재합니다
- **생성** — LLM이 리포트 섹션의 서사를 씁니다
- **검증** — Python이 그 안의 모든 숫자를 BigQuery 원본과 대조합니다

여기서 가장 중요한 결정은 **검증자를 LLM으로 두지 않은 것**입니다. 생성 결과를 다른 LLM이 심사하는 구성이 일반적이지만, 그러면 환각을 환각이 승인합니다. 조작된 숫자와 바뀐 캠페인명을 걸러낼 근거가 없습니다.

그래서 달러 금액은 BigQuery 원본 행으로 만든 표의 값 집합에 없으면 통과하지 못하도록 만들었습니다. 모델이 만들어낸 숫자는 문서에 남지 않습니다.

> This is intentionally not an LLM judge. The final report is checked against the Python-built tables and raw DB rows that came from BigQuery, so another model cannot approve hallucinated numbers or rewritten campaign names.
>
> — `report_qa_agent.py`, 코드에 남긴 설계 의도

## 규모

BigQuery 실측 · 2026.08 기준

| 지표 | 값 | 비고 |
|---|---|---|
| 누적 적재 | **1억 3,500만 행** | 약 29.7GB |
| 누적 수집 작업 | **21,607건** | 21종 report type |
| 광고 성과 커버 | **319일** | 2025.09.23 — 2026.08.09 |
| 멀티테넌트 | **41개 API 키** | sp_api 15 · advertising 14 · ads_v3 12 |
| 테이블 마이그레이션 | **239 → 1** | 날짜 샤딩 → 단일 파티션 |
| 관리 캠페인 | **296개** | 성과 레코드 48,988행 |

단일 최대 테이블은 브랜드 애널리틱스 데이터로 1억 2,952만 행 / 28.7GB입니다. 날짜 샤딩(239개 샤드) 구조를 단일 파티션 테이블로 마이그레이션해 쿼리 경로를 단순화했습니다.

## 결과

**운영** — 테넌트별 주간·월간 리포트를 자동 생성해 운영 중입니다. 최근 기준 하루 26~54개 수집 job이 돌고, 산출물은 주간 3~4분 / 월간 4~8분에 생성됩니다.

**검증 가능성** — 리포트의 모든 금액은 BigQuery 원본 행으로 만든 표의 값 집합과 대조해 통과시킵니다. 모델이 만들어낸 숫자는 문서에 남지 않습니다.

**대외** — 구축 사례가 동아일보 경제면에 보도됐습니다.

## 이 프로젝트에서 배운 것

**검증에 쓴 코드가 전체의 20%였습니다.** v3 전체 7,444줄 중 검증·교정 전용이 1,524줄입니다. 생성형 시스템에서 진짜 비용이 드는 곳은 생성이 아니라 생성물을 믿을 수 있게 만드는 부분이었습니다.

**자율성은 재현 가능성과 교환됩니다.** 에이전트가 자율 라우팅하는 구조를 먼저 만들었다가 되돌렸습니다. 같은 입력이 실행마다 다른 경로를 타면 실패를 재현할 수 없고, 재현할 수 없으면 디버깅이 성립하지 않습니다.

**AI의 역할 경계는 프롬프트가 아니라 협업으로 정합니다.** "AI가 전략까지 제안해 달라"는 요구를 받았지만, 재고·시즌성·프로모션은 데이터에 없어 모델이 추정하면 틀립니다. AI는 현상 정리까지, 전략 판단은 마케터가 맡는 것으로 합의했습니다.
