## 01. 추론을 완전히 로컬로 두었습니다

**검토했던 것**
상용 멀티모달 API를 쓰면 정확도가 높고 구현이 빠릅니다. 브라우저 에이전트의 일반적인 구성입니다.

**부딪힌 문제**
브라우저 에이전트는 화면을 봐야 하고, 화면을 보려면 스크린샷을 모델에 넘겨야 합니다. **고객사 사이트의 스크린샷이 외부 API로 나갑니다.** 로그인 후 화면, 주문 내역, 내부 관리 도구가 포함될 수 있습니다. 동의를 받기 어려운 종류의 데이터 이동입니다.

**결정**
계획은 Qwen2.5, 화면 판단은 LLaVA가 맡고 **두 모델 모두 Ollama에서 실행**합니다. 클라우드 모델 API 호출은 0건입니다.

정확도는 상용 API보다 낮지만, 애초에 쓸 수 없는 선택지와 비교할 대상이 아니었습니다.

> **정리한 것** — 제약이 설계를 만듭니다. 외부 API를 쓸 수 있었다면 Set-of-Mark도 폴백 체인도 고민하지 않았을 겁니다.

## 02. 픽셀과 DOM을 결합했습니다

**검토했던 것**
두 가지 접근이 있었습니다.

| 접근 | 방식 |
|---|---|
| DOM 기반 | 셀렉터로 요소를 찾아 조작 |
| Vision 기반 | 스크린샷을 모델에 넘기고 좌표를 받음 |

**부딪힌 문제**
DOM만 보면 **시각적으로 어떤 요소가 실제로 클릭 가능한지** 알기 어렵습니다. 숨겨진 요소, 오버레이에 가려진 버튼, 화면 밖 요소가 모두 DOM에는 존재합니다.

스크린샷만 보면 모델이 **좌표를 추측**해야 합니다. 좌표 공간 전체가 답의 후보라 정확도가 낮고, 틀렸는지 확인할 방법도 마땅치 않습니다.

**결정**
클릭 가능한 DOM 요소를 추출해 **화면 위에 번호를 붙이는 Set-of-Mark**를 사용했습니다. 모델은 전체 좌표를 추측하지 않고 제한된 후보 중 하나를 선택합니다.

> **정리한 것** — 모델에게 열린 질문을 던지지 않습니다. "어디를 클릭하나"는 좌표 공간 전체가 답이지만, "1번부터 12번 중 어느 것인가"는 선택지가 12개입니다.

## 03. 실패를 다음 실행의 자산으로 만들었습니다

**검토했던 것**
사이트마다 셀렉터를 미리 정의해 두는 방식. 안정적이지만 사이트가 늘어날 때마다 사람이 작업해야 합니다.

**부딪힌 문제**
사이트마다 UI가 다르고, 같은 사이트도 개편됩니다. 미리 정의한 셀렉터는 시간이 지나면 깨지고, 깨진 것을 알아채는 것도 사람의 일이 됩니다.

**결정**
4단계 폴백(학습 셀렉터 → Vision → 텍스트 매칭 → 좌표 클릭)으로 조작을 시도하고, **성공한 좌표에서 CSS 셀렉터를 역추적해 SQLite 신뢰도에 반영**했습니다.

같은 사이트를 다시 방문하면 학습된 셀렉터가 먼저 시도됩니다. 동작하지 않으면 신뢰도가 내려가고 자연스럽게 다른 경로로 넘어갑니다.

> **정리한 것** — 사람이 셀렉터를 관리하는 대신 시스템이 스스로 축적하게 만들었습니다. 실행할수록 빨라지는 구조입니다.

## 04. 계측 검증에 적용해 실효성을 확인했습니다

**검토했던 것**
프로토타입을 데모로 끝낼 수도 있었습니다. 로컬 멀티모달 에이전트가 동작한다는 것만 보여도 실험의 목적은 달성됩니다.

**부딪힌 문제**
"동작한다"와 "쓸모가 있다"는 다릅니다. 정형화된 데모 사이트에서 잘 도는 것은 아무것도 증명하지 않습니다.

**결정**
실제 커머스 사이트의 사용자 플로우를 탐색하며 `dataLayer` 이벤트를 수집하는 용도로 확장했습니다. 국내 주얼리 브랜드와 글로벌 F&B 프랜차이즈의 모바일 웹을 대상으로 실행해, 내부 기준 **33개 이벤트 중 80.5% 자동 검증 커버리지**를 기록했습니다.

이 경험이 재현성을 우선한 [GA4 Event Validator](../ga4-validator/)로 이어졌습니다. 자율 탐색은 커버리지에 유리하고 고정 시나리오는 재현성에 유리하다는 것을, 둘 다 만들어 보고 알았습니다.

> **정리한 것** — 실험은 실제 대상에 붙여봐야 무엇이 부족한지 알 수 있습니다. 남은 19.5%가 다음 프로젝트의 출발점이 됐습니다.

---

## 이 프로젝트의 한계

프로토타입입니다. 명시해 둡니다.

- 운영 시스템이 아니라 **가능성을 확인한 실험**입니다
- 커버리지 80.5%는 **내부 실행 기준**이며 프로덕션 SLA가 아닙니다
- 로컬 모델이라 상용 API 대비 정확도와 속도에서 불리합니다. 대신 데이터가 밖으로 나가지 않습니다
