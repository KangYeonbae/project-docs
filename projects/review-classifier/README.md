## 어떤 문제였나

커머스 운영에서 리뷰 감성 분류는 양이 많고 반복적입니다. 부정 리뷰를 빨리 찾아 대응해야 하는데, 사람이 다 읽을 수는 없습니다.

범용 LLM API로 처리하고 있었지만 두 가지가 걸렸습니다.

- **비용** — 월 10만 건 기준으로 건당 약 8원, 월 80만원 수준
- **지연** — 매 요청마다 외부 API 왕복

여기서 질문이 하나 나왔습니다. **긍정·중립·부정을 나누는 데까지 범용 LLM이 필요한가?**

라벨이 명확하고, 클래스가 3개이고, 반복량이 많습니다. 이건 전통적인 텍스트 분류 문제의 전형입니다.

## 어떻게 풀었나

AI-Hub의 라벨링된 커머스 리뷰 데이터를 정제하고 **Linear SVM과 Logistic Regression을 비교**했습니다. 가벼운 모델이라 한 번의 학습이 수십 초 안에 끝났고, 파라미터를 여러 번 조정하며 빠르게 실험할 수 있었습니다.

최종 구성은 **TF-IDF 1–2gram + Linear SVM**입니다.

### 실패한 첫 시도

처음에는 한 도메인에서만 학습했습니다. 그 도메인에서는 잘 나왔는데, **다른 상품군에서 정확도가 40%까지 떨어졌습니다.** 3-class 분류에서 40%는 사실상 무작위에 가깝습니다.

원인은 어휘였습니다. 화장품 리뷰의 "발색이 좋다"와 식품 리뷰의 "맛이 좋다"는 다른 단어 분포를 씁니다. 한 도메인의 어휘로 학습한 모델은 다른 도메인에서 근거로 삼을 특징이 없습니다.

**5개 커머스 카테고리의 리뷰 10만 건으로 학습 범위를 넓혔습니다.** 그리고 작은 테스트셋의 변동성을 줄이기 위해 고정된 분할과 클래스별 지표를 사용했습니다.

## 결과

| 지표 | 값 |
|---|---|
| 정확도 | **86.0%** (고정 테스트 분할 기준) |
| 추론 시간 | 약 **10ms** |
| 모델 크기 | **1.2MB** |
| 구성 | TF-IDF 1–2gram + Linear SVM |

**비용 비교** — 월 10만 건 동일 처리량 기준으로, 범용 LLM API는 건당 약 8원(월 약 80만원), 자체 모델은 건당 약 0.01원(월 약 1천원)으로 추산했습니다. 같은 계산 기준에서 **약 99.9%의 비용 차이**입니다.

> 이 수치는 추정입니다. 계산 근거는 월 10만 건 처리량과 당시 API 단가이며, 실제 청구액이 아닙니다.

리뷰 수집 → 판독 → 부정 리뷰 알림까지 연결해 Flask API로 제공했습니다.

## 이 프로젝트에서 배운 것

**모델의 크기가 문제 해결의 크기를 결정하지 않습니다.** 복잡한 요약이나 번역에는 큰 모델이 필요합니다. 반면 라벨이 명확하고 반복량이 많은 분류 문제에서는 작은 모델이 비용과 지연, 배포 난이도를 동시에 줄일 수 있습니다.

**작은 아티팩트는 배포까지 바꿉니다.** 1.2MB 모델은 Cloud Run이나 Lambda 같은 서버리스 환경에서 빠른 콜드 스타트와 자유로운 스케일링으로 이어집니다. 정확도만 보면 놓치는 이점입니다.

**도메인 다양성이 정확도보다 먼저입니다.** 한 도메인에서 90%를 만드는 것보다 다섯 도메인에서 86%를 만드는 편이 실제로는 쓸모 있었습니다.
